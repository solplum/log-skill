# alllog 测试门

端到端自检：验证"记录 → 跨文件去重 → 按项目汇总"主链路。用 fixtures 假数据，不碰真实会话。

## 断言清单
1. **跨文件去重**：素材目录已含 08-01、08-10 两个文件且都有 `[泡泡玛特重构]` 条目；对相同要点再次落盘 → 跳过；同项目新要点 → 正常追加（同项目多条合法）。
2. **时区**：fake-cc 的 UTC timestamp（08-11T01:30Z）转本地后 = 08-11，属所选范围，不因时区漏出。
3. **汇总归组**：读两个素材文件 → 简历素材库按项目归组，每项目含"背景/技术栈/亮点/结果/素材记录"五段。
4. **不编造**：素材无量化数据 → `**结果/量化**：待补充`，无编造数字。
5. **边界**：素材目录为空 → 提示先"全量记一下"或"全量梳理"。
6. **ZCode 源**：用 python 建临时 sqlite（`session`/`message`/`part` 三表，含 1 条起点内、1 条起点外、1 条 `synthetic=1` 注入消息），按 SKILL.md「ZCode 会话查询」跑 → 起点内会话及其真实用户消息被列出，起点外与 synthetic 被排除。
7. **闸口**：依次模拟裸调用、范围选择、项目挑选、条目确认，验证每道闸口展示选项后**结束回复停轮**，未获用户明确选择前无扫描/深读/落盘；重点防**自问自答**（同一回合提问又自行回答继续执行，2026-08-16 CC 实测事故：模型自选"最近 30 天"并"四个项目全选"）。

## 运行
把 fixtures 复制到 /tmp，按 SKILL.md 流程实跑一次汇总，逐条核对断言。
