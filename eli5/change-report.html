change-report：给上级的 git 变更报告

"这次改了什么？"——它只看 git，用老板能读的话写出来，全程只读不碰代码。
一句话类比：worklog 问的是"我这周干了啥"，change-report 问的是"这段代码改了啥"。它像一个只看监控录像的记事员：打开 git 的提交历史和改动清单，圈定一段范围，写出"改了哪、为什么改、怎么验证的"，写成一份正式备忘 + Word。它绝不 commit、push、reset——只看，不碰。

和另外两个 skill 怎么分工

📊

worklog

输入 = 聊天记录 + 口述。产出 = 本周周报。

🌿

change-report

输入 = 只有 git（status / log / diff）。产出 = 某段改动的备忘。

🗄

alllog

输入 = 全部历史。产出 = 简历素材库。

第一步永远是：圈范围

它不会自作主张选"最近 5 条提交"。它先列出候选范围让你挑：未提交的 / 已提交没推送的 / 已推送没合并的，或者你直接指定 --range / --commit / --record。没有你说清范围，它不落笔。

报告长什么样

# 变更报告 · 2026-09-30 ## 一句话目标 本次完成了发现页改版，达成了点击率提升。 ## 背景 （1–2 句正式说明） ## 本次改动 **排序混排** 原因：旧纯热度排序长尾内容曝光不足 - 发现页列表：热度 + 个性化双路混排 ## 改动文件 （只列路径，按模块分组，无代码） ## 验证结果 - 本地 24/24 测试通过

铁律：不贴代码、不写行数、不带密钥；推断不出原因写"原因待确认"，没跑测试写"未验证"，绝不编造。主题最多 1–3 个，多了问你砍哪个。

状态标记只说实话

它不会为了让流程"看起来完整"而编造一个 git 状态。

产出落在哪

报告文档/代码/<项目>/ ├── 变更记录.md ← 流水账，只追加从不覆盖 ├── md形式/2026-09-30.md ← 按范围最旧 commit 日期命名 └── word形式/2026-09-30.docx ← 委托 docx 技能渲染
