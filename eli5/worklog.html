worklog：让 AI 替你写周报

它盯着你和四个 AI 助手的全部聊天记录，把你这周干的事写成一份老板能看懂的周报。
一句话类比：你每天上班，老板周五要周报。worklog 就是一个坐在你旁边帮你记笔记的助理——你随口说一句它记一句；你没空说的时候，它自己去翻你和 Claude Code、Codex、ZCode、MiniMax Code 四个 AI 助手的聊天记录，把"这周做了什么"整理成候选清单，你点头哪些它才写哪些，最后组装成一份"需求叙事"周报。

它能干三件事

📝

随手记（模式 B）

你口述一句，它往本周的日志文件里追加一行。零摩擦，说啥记啥。

🔍

主动梳理（模式 A）

它去翻四个助手的会话记录，列出编号候选，你点名才写入。

📊

出周报

把本周日志 + 四路会话挖掘结果，合成"背景 → 方案 → 落地 → 结果"四段式周报，可导出 Word。

怎么用？就这么说

记录一下：修好了登录页白屏的 bug
梳理一下最近做了什么
周报

不用记命令，日常说人话就行。裸打 /worklog 它会先问你要哪种。

最重要的一条规矩：先问，再动手

worklog 里有"闸口"（hard gate）：每当它列完候选，必须停下来等你回复，你点名"记 1、3"它才写 1 和 3。

为什么不放心它？因为实测 AI 会"自问自答"——嘴上说"请问要记哪几条？"，下一句自己接"那我全记了"，一口气跑完。没有你的确认 = 0 条写入，这是写死在技能里的铁律。

周报长什么样

每条需求固定四段，缺数据的写"待补充"，绝不编造数字：

# 产出汇报（2026-09-28 ~ 2026-10-04） ## 需求：发现页改版 - 需求背景：旧推荐流点击率低 - 方案：热度榜 + 个性化混排 - 落地：新排序上线，AB 双桶 - 结果：点击率 +12%（或：待补充）

东西存在哪

报告文档/需求/ ├── 日志/2026-09-28.md ← 每周一命名，只追加，从不覆盖 └── 周报/ ├── md形式/2026-09-28.md └── word形式/2026-09-28.docx

日志是底账，周报是快照——重新生成周报永远不动日志。
