# 云端提交类周报

用于用户要求根据云端分支、远端提交或已推送改动写周报时。云端是取证依据；正文按“项目 → 功能主线 → 各仓具体改动”整合，不按分支排版。

## 取证范围

- 沿用已明确的项目、日期与本人工作范围。先识别实际独立仓库、远端和相关开发/集成分支；可用已确认记录定位候选，不能把同事或整个团队的提交自动算作用户工作。
- 保留原工作区与未提交改动。只读核验可使用 Git 或远端平台 API；可 `git fetch --no-tags <remote>` 更新远端引用，不 checkout、reset、pull、合并、提交、推送或部署，不运行业务接口。不要打印包含凭据的远端 URL 或配置。
- 记录核验时间、远端可达的分支与 SHA。远端不可达时说明失败；旧跟踪引用不能冒充已实时核验。除非用户接受历史快照，不用本地未推送内容补齐云端成果。

## 从多分支整合改动

### 先核对贡献归属

- 根据用户已确认的身份、协作记录及平台信息对应 Git author、committer、账号别名或共同作者；分支所属人、推送人和合并人不自动等于代码贡献者。不要只靠一个名字筛选就认领整段最终代码。
- 用本人相关提交相对父节点的差异识别实际增量；同一文件、功能涉及多人时，分开原有能力与本人补充。带教或同事提供的安装器、认证、数据源等可作为依赖背景，不写成本人从零实现。
- 作者与实际贡献不一致、代提交或归属混合时，可用已确认协作记录补足归属，但云端代码存在仍须由远端提交支持。无法确认的部分标明待确认，不计入个人已完成成果；除非用户要求团队周报，不默认汇总全团队工作。

### 再整合同仓改动

1. **确定基线与时间**：结合发布/集成基线、相关分支祖先和提交实际内容定位所选时间范围的工作；不要拿初始化 main 或错误基线比较整条历史。提交时间不等于推送时间，平台没有推送日期证据时不声称准确的推送日期。
2. **不遗漏已合入的工作**：本周提交即使已经合入发布分支仍可属于本周成果，不能只用“开发分支减当前发布 HEAD”的差集判断。必要时查看周初基线或逐提交父节点差异，区分本人增量与继承的上游改动。
3. **核对实际实现**：结合 log、show、diff 和远端版本文件确认功能及范围，不仅抄提交标题。提交声明的测试结论与实际测试回执分开；代码里存在测试不表示本次重新运行通过。
4. **同仓去重**：同一提交被多个分支包含、合并或 cherry-pick 时只记一次。结合可达关系、patch-id 或实际差异合并同一功能的多轮修复，检查撤销或替代后的有效状态。
5. **保留分支差异**：尚未合并的互斥实现不能拼成一个不存在的最终版本。能整合的改动按功能归纳并标明仓库职责；影响结论的冲突说明仍待整合，必要时询问，而不是省去差异。
6. **剔除本地范围**：未推送的技能包、界面、历史数据修复等不因会话里已有验收记录就进入云端类成果。日志与会话可补背景和定位，不得替代远端代码证据。

## 素材与正文

素材保留：项目、仓库、发生范围、贡献归属及依据、本人实际增量、相关远端 SHA、比较基线、关键路径、去重依据及交付状态。来源定位留在素材或按需附录，不将周报正文写成分支/提交清单。

正文先概括功能，再说明涉及的各仓具体改动。云端已有代码只表示已提交到远端，不自动表示合并、发布安装包、部署或业务验收；不同分支的测试数量不相加作工作量。

云端核验不属于五源会话扫描，不更新会话扫描的 `.last-scan`。正式归档与记录类使用不同文件名，遵守同一内容确认边界。
